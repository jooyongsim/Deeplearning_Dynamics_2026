Hooke's law on strain plus a dashpot along the spring — equal and opposite on the two ends

Unit direction and strain

\[\mathbf d=\frac{\mathbf x_j-\mathbf x_i}{\lVert\mathbf x_j-\mathbf x_i\rVert},\qquad \varepsilon=\frac{\lVert\mathbf x_j-\mathbf x_i\rVert}{L_0}-1\]

Spring + axial dashpot

\[\mathbf F_{ij}=k\,\varepsilon\,\mathbf d+c\,\big[(\mathbf v_j-\mathbf v_i)\cdot\mathbf d\big]\,\mathbf d\]
\[\mathbf f_i\mathrel{+}=\mathbf F_{ij},\qquad \mathbf f_j\mathrel{-}=\mathbf F_{ij}\]

\(k\) multiplies a strain, so it acts like \(E\cdot A\), not N/m. Dashpot \(c=100\).

One stiffness per spring, optimised in log space and clamped to a range

Parameterisation

\[k_s=\mathrm{clip}\big(e^{Y_s},\ Y_{\min},\ Y_{\max}\big)\]
\[Y_{\min}=0,\qquad Y_{\max}=10^5\]

Why log : \(k>0\) for free, and a gradient step changes \(k\) by a ratio, not an amount. Initial \(k=3\times10^4\).

Trap : case.spring_Y is linear, sim.wp_spring_Y is its log — exponentiate the wrong one and every spring sits at the \(10^5\) clamp.

float32 : \(\lVert\mathbf x\rVert/L_0-1\) cancels near 1 — 2.3 % force error vs float64.

Velocity first from forces, then position from the new (contact-corrected) velocity

1. Velocity from force, then drag

\[\mathbf v^{+}=\Big(\mathbf v+\frac{\mathbf f+m\mathbf g}{m}\Delta t\Big)\,e^{-c_{\text{drag}}\Delta t}\]

\(c_{\text{drag}}=3\) s\(^{-1}\) : exponential decay, never overshoots zero.

2. Contacts modify \(\mathbf v^{+}\)

3. Position (symplectic Euler)

\[\mathbf x^{+}=\mathbf x+\mathbf v^{+}\Delta t\]
\[n_{\text{sub}}=\mathrm{round}\Big(\frac{1/30}{5\times10^{-5}}\Big)=667\]

An explicit integrator must resolve the fastest spring — the stiffest, shortest one

One spring, one mass: \(\omega=\sqrt{k_{\text{eff}}/m}\)

\[k_{\text{eff}}=\frac{k}{L_0}\quad(\text{force per metre})\]

Symplectic Euler is stable for \(\omega\Delta t<2\)

\[\Delta t<2\sqrt{\frac{m\,L_0}{k}}=126.7\ \mu\text{s}\]

with \(k_{\max}=10^5\), shortest \(L_0=0.40\) mm. The dashpot limit \(2m/c=20\) ms is far looser.

Released \(\Delta t=50\ \mu\)s sits within 1.7× of the spring limit.

Tracked hand points are kinematic; springs tie them to nearby object particles

Hand points

Grounded-SAM2 hand masks + CoTracker → lifted to 3D → farthest-point sampled.

Attachment (frame 0, never changes)

\[\lVert\mathbf c_a-\mathbf p_j\rVert<0.04\ \text{m},\ \le 50\ \text{per point}\]

Inside a frame: linear interpolation

\[\mathbf c(s)=\mathbf c_{\text{prev}}+(\mathbf c_{\text{target}}-\mathbf c_{\text{prev}})\,\frac{s+1}{n_{\text{sub}}}\]

What this boundary condition means

  • A soft Dirichlet condition: prescribed motion through a compliant spring
  • Pulls as hard as it pushes
  • Never releases, never slips
  • Sparse: in single_push_rope only 2 of 30 hand points are within 40 mm

Code note: wp_control_v is never written, so the dashpot on control springs sees a control velocity of 0.

Good for fitting a video, wrong for robot grasping: a policy could “lift” the rope without ever squeezing it.

Grasp is a force latch, not a weld

  • Read normal “force” on fixed finger faces
  • Latch when both fingers exceed a threshold (3×10⁴; 4,386 after our recalibration)
  • Release when both drop below a low threshold

Ground, self- and mesh contact all edit the velocity — no penalty springs

Split relative velocity along the normal \(\mathbf n\)

\[\mathbf v_n=(\mathbf v\cdot\mathbf n)\,\mathbf n,\qquad \mathbf v_t=\mathbf v-\mathbf v_n\]

Restitution \(e\in[0,1]\)

\[\mathbf v_n'=-e\,\mathbf v_n\quad\Rightarrow\quad \lvert\Delta\mathbf v_n\rvert=(1+e)\lvert\mathbf v_n\rvert\]

Coulomb: \(\lvert\Delta\mathbf v_t\rvert\le\mu\,\lvert\Delta\mathbf v_n\rvert\)

\[\mathbf v_t'=a\,\mathbf v_t,\qquad a=\max\Big(0,\ 1-\mu(1+e)\frac{\lvert\mathbf v_n\rvert}{\lvert\mathbf v_t\rvert}\Big)\]

Reading the scale factor \(a\)

CaseMeaning
\(a=0\)stick: friction impulse can stop all sliding
\(0<a<1\)slip: slide slowed by exactly \(\mu\cdot\) normal impulse
\(a\to1\)grazing, \(\lvert\mathbf v_n\rvert\ll\lvert\mathbf v_t\rvert\)

Clamps in the kernels

\[e\in[0,1],\qquad \mu\in[0,2]\]

Same idea as the PushT impulse model — but applied per particle, per substep, with unit mass and no rotation.

If the next step would cross \(z=0\) while moving down, apply the law and split the step

Trigger

\[z+v_z\Delta t<0\ \ \text{and}\ \ v_z<-10^{-4}\]

Time of impact, then two half-moves

\[t_c=-\frac{z}{v_z},\qquad \mathbf x^{+}=\mathbf x+\mathbf v\,t_c+\mathbf v'(\Delta t-t_c)\]

Resting particle, \(e=0\)

\[\lvert\mathbf v_t'\rvert=\lvert\mathbf v_t\rvert-\mu g\Delta t\]

Gravity re-supplies \(g\Delta t\) of normal speed each substep → constant deceleration \(\mu g\) — textbook sliding friction.

What we found

In our project-13 bridge, update_collision_graph() was never called: the kernel ran 667×/frame and looped zero times. Upstream's driver does call it.

Every particle asks the BVH: “will I be inside a finger or the table next step?”

1. Predict and query (signed distance)

\[\hat{\mathbf x}=\mathbf x+\mathbf v\Delta t,\quad \text{err}=\mathrm{sign}\cdot\lVert\hat{\mathbf x}-\mathbf p\rVert-\delta\]

inside/outside by winding number; margin \(\delta\) = 5 mm (finger), 1 mm (static).

2. If err < 0: law in the finger's frame

\[\mathbf v^{\text{rel}}=\mathbf v-\mathbf V(\mathbf x),\quad \mathbf v'=\mathcal C_{e,\mu}(\mathbf v^{\text{rel}})+\mathbf V(\mathbf x)\]

Fingers: \(e=0,\ \mu=1.0\). Static: ground values.

3. Project out, read force

\[\hat{\mathbf x}\leftarrow\hat{\mathbf x}-\mathbf n\,\text{err},\qquad F_{\text{face}}\mathrel{+}=\Delta v_n/\Delta t\]

Two key tricks

Gather : each particle sums its own springs —

\[\mathbf f_i=\sum_{j}\big[k\,\varepsilon_{ij}+c\,(\mathbf v_j-\mathbf v_i)\cdot\mathbf u\big]\mathbf u\]

Local BVH : move the particle, not the mesh —

\[\mathbf x_\ell=R^{\top}(\mathbf x_w-\mathbf t)\]

Result : 3,335 launches → 1 per frame, 2 kernels per substep, every rms inside the 22.9 mm upstream self-spread.

A rope twin is springs + one velocity-level contact law, run 667 times per frame

  • Simulation model : log-stiffness springs with axial dashpots, exponential drag, symplectic Euler at 50 µs
    • \(\Delta t\) is set by the stiffest, shortest spring — 1.7× below the limit
  • Boundary condition : PhysTwin welds the hand with springs; real2sim-eval uses a moving mesh with friction
    • only the second can slip, drop, and be a fair test of a grasp
  • Contact model : \(\mathbf v_n'=-e\mathbf v_n,\ \mathbf v_t'=a\mathbf v_t\) for ground, self and mesh
    • Coulomb friction as a velocity scale factor, plus position projection
  • Cost : on a GPU, launches and refits dominate — not arithmetic, not the broad phase
  • Consequence : contact turns float round-off into mm-scale divergence — budget for it in RL and system ID

Exercises with the simulator

  • Stability : derive \(\Delta t_{\max}\) for a chain of 3 masses — when is it tighter than one spring?
  • Friction : show that \(a=0\) exactly when the needed friction impulse is \(\le\mu(1+e)\lvert\mathbf v_n\rvert\)
  • Grasp : with \(\mu=1\), what squeeze force holds a 50 g rope? Compare with the latch threshold
  • Weld vs friction : replay one trajectory in both models — where do they disagree?
  • Determinism : run the same frame 10 times with atomics, then with the gather kernel
  • Profiling : predict the CPU and GPU ranking of each kernel before you measure it
